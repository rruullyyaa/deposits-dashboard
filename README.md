# Депозиты в работе — дашборд по Bitrix24

Сайт: **https://rruullyyaa.github.io/deposits-dashboard/** (после переноса репозитория на аккаунт компании — **https://factumauto.github.io/deposits-dashboard/**).

Инструкция для человека, который будет поддерживать проект. Программировать самому не обязательно: все правки можно делать через Claude (claude.ai или Claude Code), давая ему ссылку на этот репозиторий и описывая, что нужно изменить.

---

## 1. Что показывает дашборд и для кого

Для руководителей отдела продаж/покупок Factum: как менеджеры работают с депозитами (сделки в Bitrix24 в рабочих стадиях депозита).

По каждому депозиту видно, когда в последний раз были:

| Действие | Что считается |
|---|---|
| **Звонки** | звонки (Ringostat), привязанные к сделке. Переключатель «только разговоры» — звонки от 30 секунд |
| **Комментарии** | комментарии ответственного менеджера в сделке **и его ответы в чатах задач, привязанных к сделке**. Боты (ManyChat) и очередь лидов не считаются |
| **Подборы** | комментарий в сделке со ссылкой на авто (Copart, IAAI, Manheim, Encar, Che168, bid.cars, OLX, 999.md и др.) |
| **Торги** | задачи в проекте (группе) Bitrix «1.2 Торги» |
| **Просчёты ремонта** | задачи в проекте «1.1 Расчет ремонта США/Канада» |

Вкладки сайта:

- **Депозиты** — список сделок, цвет показывает, давно ли было действие (зелёный — норма, жёлтый — скоро порог, красный — дольше порога, «нет» — не было ни разу с переноса в Bitrix ~20.09.2026). Пороги «не было ≥ N дней» переключаются кнопками.
- **По менеджерам**, **По офисам** — сводка; клик открывает депозиты менеджера/офиса.
- **Рейтинг**, **Динамика** — сравнение менеджеров и изменение «к вчера».
- **Аналитика** — «Средние на клиента» и «По дням» (выбор дат, сравнение периодов, сколько депозитов было в работе, списки торгов и просчётов со ссылками за выбранный день).
- **Ставки** — наша максимальная ставка из задачи торгов против финальной ставки лота на bid.cars: «ставка ≥ финала» (скорее всего выиграли) или «не хватило $N». Сводка по менеджерам, список лотов со ссылками; периоды «вчера / 7 / 30 дней».
- **Задачи без CRM** — торги/просчёты, поставленные **сегодня** без привязки к сделке (поле «CRM» в задаче пустое).

Фильтры: отдел, офис, менеджер. Номер сделки открывает её в Bitrix24. Телефонов и имён клиентов на сайте нет — только номера/названия сделок.

## 2. Как устроен код

```
sync.py                       ← забирает данные из Bitrix24, считает показатели, шифрует результат
site/index.html               ← весь сайт (одна страница: HTML + CSS + JavaScript)
.github/workflows/update.yml  ← расписание GitHub Actions: запускает sync.py и публикует сайт
data/finals.json              ← финальные ставки лотов с bid.cars (обновляется раз в день, см. раздел 3а)
history/seed.enc.json         ← (временный, может отсутствовать) копия истории для переноса — см. раздел 8
README.md                     ← эта инструкция
```

**sync.py** (Python 3.12, единственная зависимость — `cryptography`):
- в начале файла — настройки: `STAGES` (какие стадии воронки считать депозитами), `WIN_STAGE`, `TORG_GROUP_ID = 12` и `CALC_GROUP_ID = 10` (ID проектов «Торги» и «Расчет ремонта»), `TEAM_ROOT_DEPARTMENTS` (отделы, чьи менеджеры попадают в списки), `TALK_MIN_SEC` (с какой длительности звонок — «разговор»), `CAR_LINK` (сайты, ссылки на которые считаются подбором), `NOCRM_FROM`, `TASKLIST_DAYS`, `DAILY_KEEP_DAYS` (сколько дней хранить статистику «По дням», 400);
- функция `collect()` — все запросы к Bitrix24;
- `encrypt()` — шифрование данных паролем;
- `load_previous()` + `merge_daily()` — история: прошлые дни берутся из уже опубликованного сайта, чтобы статистика не терялась.

**site/index.html** — статическая страница без внешних библиотек и сервера. Она скачивает `data.enc.json`, расшифровывает его в браузере паролем и рисует таблицы. Пороги по умолчанию — массив `CRIT` (поле `def`).

**update.yml** — задание GitHub Actions «Обновление данных из Bitrix24» (подробнее в разделе 3).

## 3. Откуда берутся данные и как часто обновляются

Основной источник — **Bitrix24 компании** (`factum-group.bitrix24.eu`) через REST API по входящему вебхуку. Google-таблиц, внешних API и баз данных нет. Дополнительно — финальные ставки с bid.cars для вкладки «Ставки» (раздел 3а). Звонки Ringostat берутся из Bitrix (как дела сделки), к Ringostat напрямую не обращаемся.

Используемые методы Bitrix24: `crm.deal.list`, `crm.activity.list`, `crm.timeline.comment.list`, `crm.stagehistory.list`, `tasks.task.list`, `im.dialog.messages.get` (ответы в чатах задач), `user.get`, `department.get`. Только чтение — скрипт ничего не меняет в Bitrix.

Обновление — **примерно раз в час**:
1. GitHub Actions запускает `sync.py` (около :02 UTC каждого часа; запасной запуск по расписанию в :07).
2. Скрипт делает ~650 запросов к Bitrix24 (10–13 минут), шифрует результат в `site/data.enc.json`.
3. Папка `site` публикуется на GitHub Pages. Новые данные на сайте — примерно в **:15 каждого часа**. Время обновления написано в шапке сайта.

Почему так: расписание GitHub часто пропускает часы, поэтому каждый запуск в конце (задание `next`) ждёт следующего часа и сам запускает следующий. Если цепочка оборвётся, её перезапустит расписание. Публикация на Pages иногда падает с ошибкой «No artifacts named github-pages were found» — в задании три попытки публикации.

Раз в месяц задание делает пустой коммит `keepalive`, иначе GitHub отключает расписание в репозитории без изменений 60 дней.

## 3а. Финальные ставки с bid.cars (вкладка «Ставки»)

- **Наша ставка** берётся из названия задачи в «1.2 Торги» (функция `parse_bid()` в `sync.py`): «Ставка 4000 + 300 добив» → $4 300, «Ставка=8700!!» → $8 700, «уже с добивкой» — без прибавки, «кад / CAD / канадских» — ставка в CAD (не сравнивается). Лот для bid.cars — `bidcars_lot()`: Copart США → `1-<лот>` (из ссылки copart.com/lot/…), IAAI США → `0-<сток>` (8 цифр в названии). Канада и Manheim пропускаются.
- **Финальная ставка** берётся со страницы лота `https://bid.cars/en/lot/<лот>` (блок «Final bid»). bid.cars закрыт проверкой Cloudflare для серверов, поэтому GitHub Actions сам туда ходить **не может** (проверено, HTTP 403). Финалы собираются **раз в день через обычный браузер Chrome** (Claude in Chrome): по задачам торгов за 45 дней, у которых прошёл аукцион, открываются страницы лотов, результат записывается в `data/finals.json` коммитом в `main`. Ближайшее обновление сайта подхватывает файл.
- Формат `data/finals.json`: `{"updated": "<ISO-время>", "lots": {"1-78249826": {"s": "ok", "f": 4700, "d": "2026-11-27"}, …}}`, где `s`: `ok` — есть финал `f` ($), `wait` — финала ещё нет, `nf` — лота нет на bid.cars, `hidden` — финал скрыт; `d` — дата продажи на bid.cars. В файле только публичные данные bid.cars (номера лотов и цены), наших ставок и менеджеров там нет.
- Если сбор не запускался, вкладка просто показывает «ждём финал». Чтобы запустить вручную, попросите Claude: «собери финальные ставки bid.cars для дашборда» (нужен Chrome с расширением Claude и вход в Bitrix24).

## 4. Ключи, токены, вебхуки и пароли

**В коде и в репозитории секретов нет.** `sync.py` читает их только из переменных окружения, а GitHub Actions подставляет их из GitHub Secrets. Значения здесь не приводятся.

| Название | Что это | Где хранится | На чей аккаунт выпущен |
|---|---|---|---|
| `BITRIX_WEBHOOK` | адрес входящего вебхука Bitrix24 вида `https://factum-group.bitrix24.eu/rest/<id пользователя>/<токен>/`. Работает как пароль к CRM на чтение | GitHub → Settings → Secrets and variables → Actions | Bitrix24: «Входящий вебхук» **ID 109** (Разработчикам → Интеграции), создан пользователем **Руслан Кошак** (личная учётная запись). **Нужно перевыпустить на служебную/корпоративную учётную запись** — см. ниже |
| `DASH_PASSWORD` | пароль для входа на сайт (им шифруются данные) | GitHub → Settings → Secrets and variables → Actions | не привязан к аккаунту; знают Руслан Кошак и те, кому он его передал |
| `SITE_URL` | адрес сайта (необязательно, не секрет) | не задан; если нужен — переменная окружения в `update.yml` | — по умолчанию вычисляется из имени репозитория |
| `GITHUB_TOKEN` | временный токен, который GitHub сам выдаёт каждому запуску Actions (публикация, запуск следующего обновления, keepalive) | создаётся автоматически, хранить не нужно | репозиторий |

Учётные записи, на которых держится проект:

| Сервис | Аккаунт сейчас | Что сделать при передаче |
|---|---|---|
| GitHub (репозиторий, Actions, Pages) | личный `rruullyyaa` | перенести на аккаунт компании `FactumAuto` |
| Bitrix24 (вебхук) | пользователь Руслан Кошак | создать новый вебхук от служебного пользователя и заменить `BITRIX_WEBHOOK` |
| Claude (через него делались правки) | личный аккаунт Руслана | сопровождающему нужен свой аккаунт Claude |

**Как перевыпустить вебхук Bitrix24:**
1. Войти в Bitrix24 под служебным пользователем, который видит все сделки воронки «Default pipeline» и задачи в проектах «1.2 Торги» и «1.1 Расчет ремонта США/Канада» (вебхук получает права своего создателя).
2. Разработчикам → Другое → Входящий вебхук. Права: **CRM (crm), Задачи (task), Пользователи (user), Структура компании (department), Чат и уведомления (im)**. Сохранить, скопировать адрес.
3. GitHub → репозиторий → Settings → Secrets and variables → Actions → `BITRIX_WEBHOOK` → Update secret → вставить новый адрес.
4. Actions → «Обновление данных из Bitrix24» → Run workflow; убедиться, что запуск зелёный.
5. После этого старый вебхук ID 109 удалить (Разработчикам → Интеграции). Кнопка «Сгенерировать новый» в старом вебхуке меняет его адрес — сайт перестанет обновляться, пока не обновлён секрет.

Адрес вебхука никому не пересылать и не вставлять в чаты, в том числе в Claude: в GitHub его вводит человек сам.

## 5. Доступ к сайту по паролю

Сайт публичный (GitHub Pages), но без пароля открывается только экран входа. Данные лежат в `data.enc.json`, зашифрованные **AES-256-GCM**; ключ получается из пароля (PBKDF2-SHA256, 250 000 итераций). Расшифровка — только в браузере, пароль никуда не отправляется. Браузер может запомнить пароль («запомнить»), он хранится локально у пользователя.

**Сменить пароль:** GitHub → Settings → Secrets and variables → Actions → `DASH_PASSWORD` → Update secret → Actions → Run workflow. Через ~15 минут старый пароль перестанет работать; всем нужно ввести новый.

⚠️ При смене пароля история («к вчера», статистика «По дням» за прошлые дни) начинается заново: старые данные зашифрованы старым паролем. Пароль лучше менять редко (рекомендуется один раз — после передачи проекта).

Код репозитория открыт (это нужно для бесплатного GitHub Pages), но в нём нет ни ключей, ни данных.

## 6. Как внести правку и выложить на сайт

Любой коммит в ветку `main` автоматически запускает обновление: данные пересобираются и сайт публикуется (~15 минут).

**Через Claude (рекомендуется):**
1. Дать Claude ссылку на репозиторий и описать задачу простыми словами («добавь колонку…», «не считай комментарии бота…»). Полезно приложить скриншот сайта.
2. Claude меняет `sync.py` (что считать) и/или `site/index.html` (как показывать).
3. Изменённые файлы загрузить в репозиторий: на странице репозитория **Add file → Upload files** (для `site/index.html` — сначала открыть папку `site`) → **Commit changes** в `main`. Если у Claude есть доступ к GitHub, он может закоммитить сам.
4. Проверить: вкладка **Actions** → последний запуск зелёный → через ~15 минут обновить сайт (Ctrl+F5).

**Мелкие правки вручную:** открыть файл на GitHub → значок карандаша → изменить → Commit changes.

**Проверка на своём компьютере (необязательно):**
```bash
pip install cryptography
export BITRIX_WEBHOOK="<адрес вебхука>"
python sync.py                          # без DASH_PASSWORD пишет открытый site/data.json
cd site && python -m http.server 8000   # открыть http://localhost:8000
```
`site/data.json` в `.gitignore` — не коммитить его.

**Если запуск красный:** открыть его → шаг «Забрать данные из Bitrix24»: `401` / `invalid_token` — неправильный или удалённый вебхук; `insufficient_scope` — у вебхука не хватает прав (см. раздел 4). Если упал только шаг публикации — следующий запуск через час обычно проходит.

## 7. Платные сервисы

| Сервис | Для чего | Стоимость для проекта | Кто платит |
|---|---|---|---|
| GitHub (репозиторий, Actions, Pages) | код, ежечасный запуск, хостинг сайта | **0** — бесплатно для публичного репозитория. Если сделать репозиторий приватным, Pages потребует платный тариф GitHub | — |

## 8. После переноса репозитория на аккаунт компании

1. Адрес сайта меняется на `https://factumauto.github.io/deposits-dashboard/`. Старый адрес перестаёт работать (GitHub Pages не делает переадресацию) — разослать новую ссылку.
2. **Settings → Pages → Build and deployment → Source: GitHub Actions** — проверить, что стоит именно так.
3. **Settings → Secrets and variables → Actions** — проверить, что есть `BITRIX_WEBHOOK` и `DASH_PASSWORD`. Если их нет — завести заново (вебхук — уже новый, от служебного пользователя).
4. **Settings → Actions → General** — Actions разрешены; «Workflow permissions» не мешают записи (в `update.yml` права заданы явно). В настройках организации FactumAuto Actions и Pages для публичных репозиториев должны быть разрешены.
5. **Actions** → «Обновление данных из Bitrix24» → Run workflow (один раз, дальше цепочка запусков пойдёт сама). Если Actions показывает кнопку «I understand my workflows, go ahead and enable them» — нажать.
6. История: прошлые данные (статистика «По дням» за ~400 дней) раньше брались со старого адреса сайта, которого больше нет. Чтобы они не потерялись, перед переносом в репозиторий кладётся зашифрованная копия `history/seed.enc.json`; первый запуск на новом адресе подхватит её (в логе: «История: взята из history/seed.enc.json»). После первого успешного запуска файл `history/seed.enc.json` можно удалить.
7. Сменить `DASH_PASSWORD` по желанию — но лишь **после** первого успешного запуска на новом адресе (копия истории зашифрована текущим паролем), и помнить, что смена пароля обнуляет историю (раздел 5).
